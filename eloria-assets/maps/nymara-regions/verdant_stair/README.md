# Verdant Stair production map package

Verdant Stair is Nymara's terraced jungle: a limestone cliff-city climbing
south-west to north-east out of a turquoise lagoon, in eight great shelves
joined by cliff risers with waterfalls pouring off them, up to a jade temple on
the highest terrace.

The region is authored at **576 m × 576 m** — three times its original linear
extent, nine times the area — on a 96 × 96-tile server map at one metre per
tile.

This directory is the runtime package plus everything needed to rebuild it.

## Runtime files

| File | What it is |
| --- | --- |
| `world.glb` | Self-contained glTF 2.0 scene: geometry, materials and every texture embedded. No external files, no glTF extensions. |
| `references/godot-captures/` | **Real client frames** — Godot 4.7.2, Vulkan, rendered through the project's own `WorldLoader`. The delivered comparison sheets are built from these. |
| `references/captures/` | Offline previews from the authoring renderer, used to iterate and to compute the camera placements the Godot pass reuses. |
| `world.json` | GLB world manifest, schema version 1 — bounds, coordinate transform, spawns, collision and navigation declarations, terraces, landmarks, interactives, NPC and creature markers, harvestables, portals, roads, water, gorges, environment, minimap transform, provenance. |
| `world-lod2.glb` | Reduced package: far-tier vegetation only, no ground clutter, half-resolution textures. |
| `collision.bin` | Half-metre walkability grid, `EWCG` version 1, 1152 × 1152 cells over the server footprint. |
| `minimap.webp` | North-up minimap rendered from the final geometry, not drawn by hand. |
| `world.glb.validator.json` | glTF 2.0 validation report. |
| `verification-report.json` | Runtime contract report: grounding, navigation, collision and spawn checks. |
| `client-check-report.json` | The same contract measured **inside Godot 4.7.2**, through the project's own `WorldLoader`. |
| `performance-summary.md` | Triangle, node, texture and package budgets. |

## Source

`source/` holds this region's own composition and its build entry point. The
shared authoring toolkit it calls lives in `../_toolkit/`; it is pure Python
(numpy + Pillow) with one small C rasteriser used only for offline previews.
Nothing here imports a model, a texture or an asset pack: every mesh and every
texel in the package is generated by this code.

| File | What it is |
| --- | --- |
| `source/region.py` | The composition: the terrace profile, the anchors, the routes, the watercourses, the gorges, the shoreline. |
| `source/populate.py` | Eight placement passes, largest to smallest, plus the server's own population tables. |
| `source/views.py` | The camera set, the detail-board panel mapping, and this region's lighting. |
| `source/build_verdant_stair.py` | The build: GLB, manifest, collision, minimap, validation. |

```sh
cd source
python3 build_verdant_stair.py --stage terrain    # terrain and water only
python3 build_verdant_stair.py                    # the whole package
python3 ../../_toolkit/verify_runtime.py --package ..
python3 ../../_toolkit/validate_gltf.py ../world.glb
python3 ../../_toolkit/export_source_elm.py       # the 96x96 server ELM
python3 ../../_toolkit/capture_views.py           # offline preview captures
python3 ../../_toolkit/compress_captures.py       # PNG -> WebP
python3 ../../_toolkit/make_comparison.py         # concept/build sheets
```

Real client frames, which is what the delivered comparison sheets are built
from, come from Godot rather than the preview renderer:

```sh
cd ../../../../godot-client
Godot_v4.7.2-stable_win64_console.exe --path . --headless \
  --script ../eloria-assets/maps/nymara-regions/_toolkit/region_client_check.gd -- \
  --manifest=<abs>/verdant_stair/world.json --report=<abs>/client-check-report.json
Godot_v4.7.2-stable_win64_console.exe --path . \
  --script ../eloria-assets/maps/nymara-regions/_toolkit/godot_capture.gd \
  --rendering-driver vulkan --resolution 1600x1000 -- \
  --package=<abs>/verdant_stair --out=<abs>/verdant_stair/references/godot-captures
```

The build is deterministic: the same seed reproduces the same bytes. Runtime
startup never depends on rerunning it — the committed artefacts load directly.

Note the texture cache: `preview.py` keys it on a digest of `textures.py` and
`materials.py`, so editing a recipe invalidates it. It also keys on the working
directory's name, so running the build from the package and from `source/`
generates two cache files with identical contents.

## Coordinates

Right-handed, metres, Y up, north toward `-Z`. The server's 576-cell grid maps
at one metre per tile with the arrival datum at server `(174, 174)`:

```
godot_x = server_x - 174        godot_z = 174 - server_y
```

so the reachable footprint is `x ∈ [-174, 401]`, `z ∈ [-401, 174]`. Terrain is
cut 30 m larger than that on every side; the surplus is drowned to the
south-west and raised into cliff walls elsewhere, so a character cannot reach an
unfinished void.

The whole composition is written in **stair coordinates** — `s = (x - z) / 2`
up the diagonal, `c = (x + z) / 2` along a terrace — and `s` alone decides which
shelf a place stands on. See `modeling-assumptions.md`.

## The stair

| Terrace | Height | What is on it |
| --- | ---: | --- |
| seabed | −13 m | the lagoon and its inlet |
| strand | 0.4 m | beach, boat landing, the Westhaven quay |
| quay | 7 m | west quay and market |
| lower | 24 m | the arrival town, the waygate, the foot of the Grand Stair |
| middle | 46 m | the cenote, the canopy village, the gorge crossings |
| upper | 72 m | the water shrine, the aqueduct, the hanging gardens |
| temple | 100 m | the Green Temple and its court |
| summit | 124 m | the ridge, the quarry, the Ssarathi pass |

**This needs a matching server map.** `../source-elm/verdant_stair.elm` is
regenerated here at 96 × 96 tiles (576 × 576 height cells) with real elevation
and walkability, replacing the flat 32 × 32 placeholder. The matching server
change is `johodges/eloria-server` `feature/verdant-stair-576m-server-map`; the
two must land together, because the client manifest declares
`serverOrigin [174, 174]`. See `validation-report.md` for what the server does
and does not currently do with the regenerated ELM.

## Navigation contract

The Godot client turns every `MeshInstance3D` whose name begins with an entry in
`navigation.surfaceNodePrefixes` into collision on its navigation layer, then
grounds actors with a downward ray from y = 400. This package uses two
prefixes:

* `Terrain_` — the eight terrain surface classes.
* `Walk_` — authored walkable decks only: stair treads, bridge decks, plank
  walkways, canopy platforms, hut decks, the quay, the cenote stair and the
  pavilion floors.

Structural geometry — terrace retaining walls, the temple mass, arcade piers,
tree trunks, balustrades — is deliberately **not** a walk surface, so the
grounding ray never snaps a character onto a roof or the top of a wall.
`_toolkit/verify_runtime.py` casts that exact ray at all **331,776** reachable
server tiles and reports **zero misses**.
